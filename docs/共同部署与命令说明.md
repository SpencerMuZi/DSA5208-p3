# 三人共同部署与命令说明

阅读对象：全员。各人执行自己的角色指南；本文件解释共同步骤及每条命令用途。请按顺序执行，错误先解决再继续，不把失败输出直接忽略。

## 0. 终端位置约定

| 标签 | 执行位置 |
|---|---|
| Windows 本机 | Windows Terminal / PowerShell，尚未 SSH |
| Mac 本机 | Terminal，尚未 SSH |
| 集群登录节点 | SSH 登录后的 Linux bash；管理文件、编译、提交 |
| 集群计算节点 | 调度器已分配资源，或 PBS 脚本自动执行 |

没有经过 `qsub`/学校认可的交互式资源分配，不直接运行性能命令。下文所有测量通过 PBS 提交。

## 1. 获得账号和网络访问

1. 三人分别查看课程 Canvas/TA 说明以及 [HPC 账号入口](https://nusit.nus.edu.sg/hpc/get-an-hpc-account/)。注册/审批按学校网页完成。
2. 获取实际集群登录主机、个人账号、课程项目/CPU 队列、允许的节点数/核数/时限。不要使用别人的密码。
3. 校外连接使用学校当前 VPN 说明；不能连主机时先排查网络，再排查账号。
4. 本包以 PBS+Open MPI 为目标。登录后若学校提供另一种 MPI，先采用官方模块/启动方式适配，不能套 Open MPI 的参数。

我们没有你们的账号，也没有核实 DSA5208 当前队列和 module 名称，因此这些值必须实际填写。`SITE_CONFIRMED=0` 会阻止生成作业，避免未确认的配置被误当成可运行命令。

## 2. Windows 本机上传（A/B）

先把 `DSA5208_Project3_source.zip` 下载到“下载”文件夹。打开 PowerShell，逐行运行。A 使用 `DSA5208_P3_A`，B 替换成 `DSA5208_P3_B`。

```powershell
Get-Command ssh
Get-Command scp
$HpcUser = Read-Host '输入个人 NUSNET ID'
$HpcHost = Read-Host '输入课程确认的集群登录主机'
$RemoteDir = 'DSA5208_P3_A'
$ZipPath = Join-Path $env:USERPROFILE 'Downloads\DSA5208_Project3_source.zip'
Test-Path $ZipPath
Get-FileHash $ZipPath -Algorithm SHA256
ssh "${HpcUser}@${HpcHost}" "mkdir -p $RemoteDir"
scp $ZipPath "${HpcUser}@${HpcHost}:${RemoteDir}/source.zip"
ssh "${HpcUser}@${HpcHost}"
```

前两行确认 SSH/SCP 存在，`Test-Path` 应返回 True。首次连接核对学校提供的 host fingerprint；出现主机变化错误先核实，不盲目删除 known_hosts。密码由 SSH 正常提示输入，不写进脚本。

如果系统没有 SSH，可通过 Windows 设置安装 OpenSSH Client，或按学校指南用其认可客户端。上传也可用学校支持的网页文件管理器；上传后仍从角色对应目录解压。无需安装 WSL、Docker、Visual Studio 或本地 MPI。

## 3. Mac 本机上传（C）

把同一个 ZIP 下载到 Downloads。Terminal 逐行执行：

```bash
command -v ssh
command -v scp
read -r 'HpcUser?输入个人 NUSNET ID: '
read -r 'HpcHost?输入课程确认的集群登录主机: '
RemoteDir=DSA5208_P3_C
ZipPath="$HOME/Downloads/DSA5208_Project3_source.zip"
test -f "$ZipPath"
shasum -a 256 "$ZipPath"
ssh "${HpcUser}@${HpcHost}" "mkdir -p $RemoteDir"
scp "$ZipPath" "${HpcUser}@${HpcHost}:${RemoteDir}/source.zip"
ssh "${HpcUser}@${HpcHost}"
```

这里的 `read -r '变量?提示'` 是 Mac 默认 zsh 写法；若改用 bash，用 `read -r -p '提示' HpcUser` 和相应 HpcHost 行。三人 ZIP hash 必须一致。

## 4. 登录后解压并识别环境

以下是集群 Linux bash 命令；A/B/C 分别替换第一行最后的角色字母。

```bash
cd "$HOME/DSA5208_P3_A"
python3 -m zipfile -e source.zip .
cd Project3
pwd
ls
bash -l scripts/detect_env.sh
```

`pwd` 应结束于 `DSA5208_P3_A/Project3`。`ls` 应看到 Makefile、src、scripts、docs、configs、README.md。

`detect_env.sh` 保存编译器路径、module、MPI 版本、PBS 命令/队列信息等。它不会申请/运行性能作业。此时打印的 lscpu 是登录节点规格，不能作为报告中计算节点规格；正式作业另外保存计算节点环境。

模块发现可逐行执行（命令必须存在）：

```bash
type module
module avail
module list
command -v qsub
qstat -Q
```

如果 `type module` 失败，按学校说明初始化 module 或通过 login shell；不要随意把外部机器路径复制进集群。`qstat -Q` 显示的队列不等于你有使用权限，以课程确认信息为准。

## 5. 填写两个配置文件

```bash
cp configs/site_modules.sh.example configs/site_modules.sh
cp configs/cluster.env.example configs/cluster.env
nano configs/site_modules.sh
```

在 nano 中，用课程真实模块名替换注释示例，形成例如下面的结构；`真实...` 是说明文字，不是可执行的模块名：

```text
module load 真实编译器模块名
module load 真实OpenMPI模块名
export SERIAL_CXX=g++
export MPI_CXX=mpicxx
export PROJECT_CXXFLAGS='-O3 -std=c++17 -Wall -Wextra -Wpedantic'
export PROJECT_OPENMP_FLAGS='-fopenmp'
export PROJECT_LDFLAGS=''
```

若不需加载模块，可以保留已正确可用的编译器设置。MPI wrapper 后端与串行编译器应一致；先用 `mpicxx --showme:command`（Open MPI）查看。此项目默认 GCC 的 `-fopenmp`；不同编译器要改成其支持的参数。nano 保存：Ctrl+O、Enter；退出：Ctrl+X。

```bash
source configs/site_modules.sh
command -v g++
command -v mpicxx
mpicxx --showme:command
mpicxx --version
mpirun --version
nano configs/cluster.env
```

需要逐项填写：

| 配置 | 怎样填写 |
|---|---|
| CLUSTER_NAME | 实际 `Atlas` 或 `Vanda` |
| SCHEDULER | 确认使用 PBS 才填 `PBS` |
| QUEUE | 课程允许的真实 CPU 队列；确认可默认路由才留空 |
| PROJECT_CODE | 课程项目 code；确认不需要才留空 |
| PROJECT_FLAG | 官方要求 `-P` 或 `-A` |
| MPI_FLAVOR | 使用 Open MPI 才填 `openmpi` |
| MPI_PBS_INTEGRATED | 核实该 module 的 Open MPI 可读取 PBS allocation 才填 1 |
| MAX_CPUS_PER_NODE | 本课程允许你们申请的上限，初期可保守设 8 |
| MEMORY_PER_NODE | 单个 PBS chunk 内存请求，按问题规模和配额选择 |
| WALLTIME | 作业总时限，包含所有 repetitions/warmup/launcher 的时间 |
| OMP_PLACES / OMP_PROC_BIND | 初版 `cores` / `close` |
| SITE_CONFIRMED | 上述核实完成后设 1 |

若 MPI/PBS integration 未知，查官方示例或问 TA；不要通过编造 hostfile、SSH 到未获配节点或 `--oversubscribe` 绕过资源分配。模板未确认不会生成作业。

内存估算：串行主要有 3 个 double 网格，约 `24*(N+2)^2` 字节；N=2048 时约 101 MB，另加进程/MPI/输出开销。并行每 rank 存局部行；小测试默认 2gb/chunk 只是可调整的起点。

## 6. 编译并保存编译信息

集群登录节点轻量编译，学校若要求在 build/compute 节点编译则按其规则执行：

```bash
bash -l scripts/build.sh
ls -l bin
cat results/build/build.txt
cat results/build/compile.txt
bin/jacobi_serial --help
```

应出现 jacobi_serial、jacobi_parallel、hello_hybrid。`--help` 不运行求解器。每次更换编译器/MPI/优化参数都执行 `build.sh`，它会清理旧可执行文件。

## 7. 第一个双节点 smoke 作业

三人分别执行：

```bash
python3 scripts/make_jobs.py --preset smoke --iters 100 --repeats 3
JOB_DIR=$(ls -td jobs/generated/smoke-* | head -n 1)
cat "$JOB_DIR/manifest.json"
cat "$JOB_DIR/p3-smoke-1.pbs"
bash -n "$JOB_DIR/p3-smoke-1.pbs"
JOB_ID=$(qsub "$JOB_DIR/p3-smoke-1.pbs")
printf '%s\n' "$JOB_ID"
qstat -f "$JOB_ID"
```

前六行只生成和审核，`qsub` 是真正提交。检查 select=2、每节点 ncpus=2、mpiprocs=1、ompthreads=2，队列/项目/时限正确。该 smoke 用两个 MPI ranks、每 rank 两线程、N=31，并首先运行 hello_hybrid 检查实际节点与线程。

`qstat` 中 Q 为排队、R 为运行。完成后作业可能从默认 qstat 消失；消失不自动等于成功。若站点支持，可查 `qstat -xf "$JOB_ID"`，并检查本地输出和完整标记。

```bash
ls -lt p3-smoke-1.o*
tail -n 80 p3-smoke-1.o*
ls -td results/raw/* | head -n 3
```

默认 PBS 输出文件名可能由站点修改；找不到 `.o*` 时查看 `qstat -f` 的 Output_Path。为最近结果目录赋值并检查：

```bash
RUN_DIR=$(ls -td results/raw/* | head -n 1)
cat "$RUN_DIR/metadata.json"
cat "$RUN_DIR/topology.stdout.jsonl"
cat "$RUN_DIR/repeat-1.stdout.txt"
cat "$RUN_DIR/COMPLETE"
```

成功标准：topology 有两条 rank、两个不同 host、每 rank threads=2；measurements 存在、COMPLETE 存在、无 solver 错误。不能把 topology 中重复两次同一 host 视为双节点运行。

## 8. 完整正确性作业

```bash
python3 scripts/make_jobs.py --preset verify
JOB_DIR=$(ls -td jobs/generated/verify-* | head -n 1)
cat "$JOB_DIR/p3-verify-1.pbs"
JOB_ID=$(qsub "$JOB_DIR/p3-verify-1.pbs")
qstat -f "$JOB_ID"
```

该作业申请单节点 4 核，测试程序只选择不超过 4 核的 rank/thread 配置，不会把 4 ranks×4 threads 挤进 4 核。完成后：

```bash
ls -lt p3-verify-1.o*
tail -n 80 p3-verify-1.o*
VALIDATION_DIR=$(ls -td results/validation/* | head -n 1)
cat "$VALIDATION_DIR/summary.json"
```

需 PASS、summary 的 passed=true；记录 scope、checks 和测试条件。不同版本脚本的检查数可能变化，按实际日志填写。

## 9. 管理作业和批量提交

```bash
qstat -u "$USER"
```

仅在确认某个作业需要取消时，用其真实 ID：

```bash
read -r -p '输入要取消的本人作业 ID: ' CancelJobId
qdel "$CancelJobId"
```

不要取消别人的作业，也不要用未经核实的全队列清理命令。

某个矩阵生成之后，先检查每个脚本资源，再少量提交：

```bash
for script in "$JOB_DIR"/*.pbs; do
    cat "$script"
done
```

资源/配额/脚本确认后：

```bash
for script in "$JOB_DIR"/*.pbs; do
    qsub "$script"
done
```

开始时一次只提交 1–2 个；确认 walltime、测量持续时间和结果后再提交完整矩阵。作业数不是同时运行数，需遵守课程提交限制。

## 10. 下载结果与交接

集群登录节点中创建角色归档，A 使用 A、B 使用 B、C 使用 C：

```bash
tar -czf ../A_results.tar.gz results jobs/generated
sha256sum ../A_results.tar.gz

```

Windows PowerShell 本机，变量若已关闭窗口则重新赋值：

```powershell
scp "${HpcUser}@${HpcHost}:${RemoteDir}/A_results.tar.gz" "$env:USERPROFILE\Downloads\A_results.tar.gz"
Get-FileHash "$env:USERPROFILE\Downloads\A_results.tar.gz" -Algorithm SHA256
```

Mac 本机：

```bash
scp "${HpcUser}@${HpcHost}:${RemoteDir}/C_results.tar.gz" "$HOME/Downloads/C_results.tar.gz"

```

下载 hash 应与集群一致。A/B 把各自归档与 hash 交给 C；只分享结果，不分享账号密码。

## 11. 常见错误定位

| 错误 | 下一步 |
|---|---|
| SSH timeout / connection refused | 检查主机、学校网络/VPN、账号是否开通 |
| Permission denied | 核实个人 NUS ID、HPC 注册、密码/MFA 指南 |
| module: command not found | 使用 login shell / 官方模块初始化，查看 detect 输出 |
| mpicxx not found | 加载课程 MPI module，重跑 command -v |
| omp.h / OpenMP link 错误 | 核实编译器与 OpenMP 参数；不要沿用 Mac 的参数到 GCC Linux |
| qsub 未授权 queue/project | 回查课程批准的队列和 project flag/code |
| PE / binding not enough CPUs | 核实 ncpus=ppn×threads、MPI 与 PBS integration、CPU masks |
| topology host 数错误 | 查看实际 allocation 与 launcher；不能继续把结果当跨节点实验 |
| MPI 阻塞挂住 | 停止该作业，查看 tag、发送/接收邻居与一致的循环/检查条件 |
| solve exit 2 | 没达到容差；增加 max_iters 或检查程序，不能记成已收敛 |
| 最短运行只有毫秒级 | 增加统一迭代数，重新预跑并冻结矩阵参数 |
| analyzer speedup 为空 | 缺少同 cluster/CPU/source/build/workload/family 的 serial 基线 |

本指南给出可执行步骤，但当前未知的账号、queue、modules 和课程配额无法预先写成真实常量。确认配置后，生成器会把具体设置写进每份可审阅的 PBS 文件。
