## 5. 算法与代码入口

在 [0,1]²、零边界求解 -Δu=f。N 是每维内部点数，h=1/(N+1)。更新：

```text
new[i,j] = (old[i-1,j]+old[i+1,j]+old[i,j-1]+old[i,j+1]+h²*f[i,j])/4
```

`old/new` 双数组交换，不原地更新。每个 MPI rank 分配 N/p 行，加上下 halo 各一行；余数行先分给 rank 0、1 等。MPI ranks>N 时明确报错。

| 文件 / 函数 | 作用 | 主要阅读者 |
|---|---|---|
| src/common.hpp / parse_options | 参数约束、JSON 格式、问题定义 | 全员 |
| src/serial.cpp / residual | 真正单线程参考、残差、解析解误差 | A |
| src/parallel.cpp / rows, offset | 均匀分区与余数行 | B |
| exchange_blocking | 上下邻居 Sendrecv | B |
| update | 本地 OpenMP static 循环 | C |
| overlap 分支 | Irecv/Isend → 内部行 → Waitall → 边缘行 | B/C |
| residual | 更新当前 halo → 局部残差 → Allreduce | A/B |
| src/hello_hybrid.cpp | 实际 hosts、线程数、Linux thread CPU masks | C |
| scripts/validate.py | 串并行逐点比较、解析解、拒绝未收敛 | A |
| scripts/benchmark.py | warmup、重复、命令与环境证据 | C |
| scripts/make_jobs.py | 经确认配置生成 PBS，无自动提交 | C |
| scripts/analyze.py | 基线匹配、统计、图表 | C/A |

代码中的 phase timing 是可选诊断，不是默认正式测量。`profile=false` 时没有每阶段 Wtime 调用；所有 MPI 配置仍在循环起点 barrier，然后取各 rank 的 elapsed time 最大值。

## 6. 核心验证

构造解 u*=x(1-x)y(1-y)，f=2[x(1-x)+y(1-y)]。中心差分对这个多项式的二阶导数精确（除舍入），因此网格采样值就是离散系统的参考解。

`validate.py` 包括：

- N=1、3、4、5、17、31、64，固定 37 轮，逐点串并行比较。
- ranks=1/2/3/4、threads=1/2/4/8，在 `--max-cores` 限制内选组合；单节点 4 核的 verify 仅选择总线程数不超过 4 的组合。
- 不整除、一行/两行 rank、MPI/混合/overlap。
- N=17/31，solve 模式达到残差 1e-8，检查解析解误差。
- 最大迭代数不足时 exit 2、错误 N 的拒绝与空分区拒绝。

成功显示 PASS 并写 `results/validation/.../summary.json`。失败时不继续正式实验，保留 stdout/stderr 与 command.json 排查。

## 7. 正式实验安排

先确认每节点可用 CPU。下面以每节点使用 8 核为小规模示例，不声明任何机器实际只有 8 核。

| 矩阵 | 初版数量 | 具体设置 |
|---|---:|---|
| strong，A | 每个 N 10 个配置 | serial；MPI 1/2/4/8/16 核；hybrid 每 rank 两线程、2/4/8/16 核 |
| weak，C | 5 个配置 | 1/2/4/8/16 核，N≈256√C，固定轮数 |
| mix，C | 8 个配置 | 1/2 节点，各 8 核/节点，threads=1/2/4/8 |
| comm，B | 4 个核心配置 | 1/2 节点，threads=2，比较 hybrid/overlap |
| check，可选 | 3 个配置 | N=64 单节点，solve、q=1/10/50 |

建议 strong 用 N=512、1024 两档，预跑后再加 2048。每配置先 warmup，再测 5 次；预跑可 3 次、100 或 200 轮。

若单次求解循环明显短于约 0.1–0.2 秒，先增加迭代次数，避免测量噪声主导。所有需要比较的配置必须保持相同轮数。示例 1000 轮只是起点，不保证足够长。

正式 strong 固定迭代次数和 check=0；weak 同样固定轮数。最后仍在计时外输出残差。它们研究固定工作量，不声称已经收敛。solve 对照固定残差容差，并记录停止迭代数。

S(C)=Tserial/Tparallel(C)，E(C)=S(C)/C，C=p×t。C 是使用的 CPU 执行资源数，需确认物理核/硬件线程设置，记录调度器分配及 actual masks。

## 8. 证据与分析规则

每次测量保存 job ID、cluster、hosts、节点数、CPU model、编译信息、source hash、binary hash、参数、真实 topology、warmup 和每次原始 JSON。

- `COMPLETE` 存在才汇总；失败或超时作业单独排查。
- 不同 CPU、代码、编译参数、问题/轮数/容差的记录不合并。
- 缺 serial 基线时 speedup 留空。不要拿本机数据或 MPI 单 rank 数据替代却不标注。
- min/max error bars 表示本次重复范围，不是置信区间。
- 非阻塞等待更短不一定总时间更短；最终以总循环时间为主要比较。
- 所有阶段的各 rank 最大时间可能来自不同 rank，不可相加作为准确总时间。
